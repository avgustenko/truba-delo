# Как мы работаем с GitHub

Решение владельца (15.10.2026): «Давай будем использовать всё остальное, то, что мы не использовали. Распиши везде, чтобы у всех были эти правила». Правила общие для всех репозиториев владельца; здесь — как они устроены в `avgustenko/truba-delo` (страница отчёта по производственной практике, один файл `index.html`). Обязательно для всех — людей и нейросетей.

**Репозиторий открытый:** всё, что в нём лежит, видят все. Секреты (пароли, ключи, токены), данные клиентов и снимки рабочей системы «Труба-Дело» сюда не класть.

1. **Журнал изменений.** Любое изменение — запись в [CHANGELOG.md](CHANGELOG.md) в том же коммите: когда (по Екатеринбургу), кто, зачем, что и где. Проверка «Журнал изменений» в Actions без записи становится красной.
2. **Задачи — Issues.** Каждая просьба владельца — задача: «Просьба» или «Ошибка» (шаблоны — `.github/ISSUE_TEMPLATE/`). В коммите с правкой — `Закрывает #номер`, в журнале — «Задача: #номер».
3. **Pull request** — для большой переделки страницы, по шаблону `.github/pull_request_template.md`. Мелкие правки — сразу в `main`.
4. **Версии.** После правок — Actions → «Версия» → Run workflow: метка `vГГГГ.ММ.ДД` и страница в Releases со списком правок ставятся сами.
5. **Dependabot** раз в месяц предлагает обновить действия Actions (библиотек у страницы нет). Принять: дописать в его ветку запись в журнал → слить.
6. Сообщения коммитов — по-русски: первая строка — что сделано, ниже — подробности.
